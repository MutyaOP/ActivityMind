# ActivityMind — архитектура

## Компоненты
```
┌─────────────────┐  HTTPS + token   ┌──────────────────────────────┐
│ Desktop Agent   │ ───────────────► │   Laravel Web Platform       │
│ Python, Windows │  (REST)          │   Blade + Tailwind + Chart.js│
│ SQLite (буфер)  │                  │   MySQL                      │
└─────────────────┘                  └───────┬───────────┬──────────┘
                                             │           │
                                  HTTP (5 с) │           │ (план)
                                             ▼           ▼
                                    ┌──────────────┐
                                    │ AI Analyzer  │
                                    │ Pandas,      │
                                    │ Scikit-learn │
                                    └──────────────┘
```
Реализовано: Laravel-платформа, Agent API (токены устройств), Desktop Agent (Python), AI-модуль (Python: Flask, Pandas, Scikit-learn).
Запланировано: редактор категорий, экспорт отчётов, уведомления.

## Слои Laravel (MVC + сервисный слой)
| Слой | Ответственность |
|---|---|
| Routes (`routes/web.php`) | точки входа; группы `auth` и `auth + admin` |
| Middleware | `auth`, `admin` (`EnsureUserIsAdmin`), `throttle` на генерации советов |
| Controllers | тонкие: валидация → сервис → ответ |
| Form Requests | валидация (`TaskRequest`, `HabitRequest`) |
| Policies | доступ к данным только владельцу (`Task`, `TimeEntry`, `Habit`, `Recommendation`) |
| Services | вся бизнес-логика (таблица ниже) |
| Models (Eloquent) | связи, casts, scopes |
| Views (Blade) | layout с боковым меню, компоненты, страницы модулей |
| Console | команды `activitymind:*` для расписания и демо-данных |

## Сервисы
| Сервис | Что делает |
|---|---|
| `TimerService` | старт (останавливает предыдущий), стоп, ручная запись |
| `HabitService` | отметка дня, серии (daily/weekly), процент выполнения, сетка 7 дней |
| `AnalyticsService` | данные дашборда, формула «продуктивность дня» (`score`) |
| `StatsService` | расчёт и `upsert` в `daily_stats`; данные страницы «Аналитика» |
| `RecommendationService` | правила советов, паузы, ограничение за запуск, вызов AI-клиента |
| `AppCategorizer` | категория приложения по имени процесса и заголовку окна (для данных агента) |
| `AiAnalyzerClient` | HTTP-клиент к AI-модулю; при ошибке или без настройки — молча выключен |

## Поток данных
```
Таймер / задачи / привычки ──► time_entries, tasks, habit_logs        Desktop Agent ──► activity_logs
                                      │
                     StatsService::sync (upsert)
                                      ▼
                                daily_stats ──► Аналитика (графики, выводы)
```

## AI-модуль
Отдельный процесс, который сайт вызывает по HTTP (`POST /analyze`, таймаут 5 с). Он ничего не хранит и не знает о пользователях: на вход — агрегаты по 14 дням (`daily_stats` + распределение по часам), на выход — до трёх выводов `{key, type, text}`.

| Метод | Библиотека | Вывод |
|---|---|---|
| линейная регрессия по часам фокуса | scikit-learn | тренд роста или падения (с R²) |
| группировка по дням недели | pandas | слабый и сильный день недели |
| коэффициент вариации | pandas / numpy | неустойчивый ритм |
| сравнение групп дней по доле привычек | pandas | связь привычек с фокусом |
| доля дней без закрытых задач | pandas | «много времени — мало результата» |

Правила остаются основой, AI добавляется поверх: если модуль выключен, недоступен или ответил ошибкой, сайт продолжает работать. Повторы исключает стабильный `key` вывода + пауза правила (`rule_key = ai_<key>`).

## Принятые решения
- **Время:** в БД UTC; границы «дня» считаются в поясе пользователя.
- **Один таймер:** запуск нового останавливает предыдущий — нет пересекающихся записей.
- **Аналитика «на лету» + кэш в `daily_stats`:** страница сама пересчитывает период, поэтому данные не устаревают; таблица нужна для истории, быстрого доступа и AI-модуля.
- **Рекомендации по правилам с паузами:** предсказуемо, объяснимо в дипломе, не засоряет ленту; AI добавляется поверх, не заменяя правила.
- **Переносимые SQL-запросы:** без функций, специфичных для MySQL (`FIELD()` заменён на `CASE`), поэтому тесты идут на SQLite в памяти, а приложение — на MySQL.
